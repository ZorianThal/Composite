Практическое задание
Паттерн Composite — Компоновщик
Тема

Разработать небольшую систему управления группами игровых персонажей с использованием паттерна Composite.

Задача

Создать программу, в которой можно работать как с отдельным персонажем, так и с группой персонажей через один общий интерфейс.

1. Требования

Создайте интерфейс:

interface IUnit
{
    void Attack();
}

Создайте минимум два обычных персонажа:

Warrior
Mage

Каждый персонаж должен реализовывать IUnit.

Например:

Warrior → "Воин атакует мечом!"
Mage    → "Маг атакует заклинанием!"
2. Создайте класс Squad

Squad также должен реализовывать:

IUnit

Внутри Squad должен находиться список:

List<IUnit>

Добавьте метод:

Add(IUnit unit)

Он должен добавлять персонажа или другую группу в отряд.

3. Главное условие

Должно быть возможно написать:

IUnit warrior = new Warrior();

IUnit squad = new Squad();

squad.Add(warrior);

А затем:

squad.Attack();

И программа должна вызвать атаку всех объектов внутри группы.

4. Обязательно реализовать вложенные группы

Например:

Главный отряд
│
├── Воин
├── Маг
│
└── Второй отряд
     │
     ├── Воин
     └── Маг

В Main() необходимо создать такую структуру.

При вызове:

mainSquad.Attack();

атаковать должны все персонажи, включая персонажей во вложенной группе.

5. Пример результата
Главный отряд атакует!

Воин атакует мечом!
Маг атакует заклинанием!

Второй отряд атакует!

Воин атакует мечом!
Маг атакует заклинанием!

Конкретный текст можно сделать своим.

6. Дополнительное задание

Добавьте:

Archer

и возможность создавать группы внутри групп.

Например:

Армия
│
├── Отряд 1
│    ├── Warrior
│    └── Archer
│
├── Отряд 2
│    ├── Mage
│    └── Mage
│
└── Отряд 3
     └── Warrior

При:

army.Attack();

должны атаковать все персонажи.

7. Ограничения

Нельзя:

создавать отдельный класс для каждой комбинации;
проверять тип объекта через if;
использовать switch для определения типа персонажа;
писать отдельную логику для каждой возможной группы;
делать отдельные методы вроде AttackWarriors(), AttackMages() и т. п.

Обязательно использовать:

IUnit

и:

List<IUnit>
